# LectureAI — ИИ-помощник для подготовки учебных материалов по лекции

**Команда BRILLIANTS** · репозиторий хакатона: https://github.com/BAITC-Hacks/hack-6a16025e-brilliants

Веб-прототип для трека «Образовательные технологии». Студент вставляет расшифровку лекции, и LectureAI за 10–15 секунд создаёт **конспект**, **тезисы**, **тест с правильными ответами** и **карточки для повторения**. Всё строится только на тексте лекции, а каждый тезис, вопрос и карточка показывает дословную цитату, на которую опирается.

## Какую проблему решает

После лекции студент тратит часы на разбор записи: пишет конспект, придумывает вопросы для самопроверки, делает карточки. При ручной работе легко пропустить тему или записать её неточно. LectureAI делает это автоматически и привязывает каждый материал к конкретному фрагменту лекции, чтобы студент (и жюри) могли проверить точность.

## Путь пользователя

1. Вставить текст лекции (или нажать «Вставить пример лекции»).
2. Нажать «Сгенерировать материалы» (или `Ctrl + Enter`).
3. Прочитать **Конспект**, затем кнопкой «Проверить знания» перейти в **Тест**.
4. Пройти тест: после каждого ответа видно, верно ли, пояснение и цитата из лекции.
5. Кнопкой «К карточкам» перейти к **Карточкам** и повторить сложные темы.
6. При необходимости нажать «Сгенерировать заново» или «Скачать .md».

## Запуск

Нужен **Node.js 20+** и бесплатный API-ключ Groq: https://console.groq.com/keys

```bash
git clone https://github.com/BAITC-Hacks/hack-6a16025e-brilliants.git
cd hack-6a16025e-brilliants
npm install
npm run dev
```

Откройте http://localhost:5173 и вставьте API-ключ Groq в поле «API-ключ Groq» в правом верхнем углу. Ключ сохраняется только в `localStorage` вашего браузера.

Чтобы ключ подставлялся автоматически на локальном демо, создайте файл `.env.local` (он в `.gitignore`, в репозиторий не попадёт):

```bash
cp .env.example .env.local
# затем впишите: VITE_GROQ_API_KEY=gsk_...
```

Production-сборка: `npm run build`, затем `npm run preview`.

## Реализованные функции

- **Конспект**: связный пересказ лекции в 2–4 абзацах с названием темы.
- **Тезисы**: 5–8 отдельных главных мыслей, у каждой цитата-источник из лекции.
- **Тест**: 5–8 вопросов с 4 вариантами, мгновенная проверка (верно/неверно), пояснение, цитата, счёт и итог; переход к карточкам после теста.
- **Карточки**: 6–10 карточек «термин/вопрос → ответ» с 3D-переворотом и цитатой на обороте.
- **Проверка достоверности**: каждая цитата автоматически сверяется с исходным текстом (дословное совпадение без учёта регистра и пунктуации либо ≥ 80 % совпадающих словесных триграмм). Сводка «N из M материалов подтверждены цитатой» видна в конспекте; если фрагмент не найден, элемент честно помечен «Обобщение по лекции — дословный фрагмент не найден».
- **Повторная обработка**: кнопка «Сгенерировать заново».
- **Состояния обработки**: скелетон и пошаговый индикатор во время генерации, блокировка повторного клика.
- **Обработка ошибок** (понятные сообщения, приложение не падает):
  - пустое поле;
  - текст короче 50 символов;
  - текст длиннее 40 000 символов;
  - бессвязный набор символов (локальная эвристика: доля букв, наличие гласных, разнообразие символов);
  - осмысленный, но не учебный текст (модель возвращает `is_lecture: false` с причиной);
  - нет или неверный API-ключ (401/403), лимит запросов (429), слишком длинный запрос (413), нет сети, таймаут 90 с.
- **Экспорт** в Markdown (`Скачать .md`).

## Как это работает

```
Текст лекции → локальная валидация → Groq Chat Completions (строгий JSON Schema)
            → проверка структуры → сверка цитат с лекцией → перемешивание вариантов → интерфейс
```

- **Модель:** `openai/gpt-oss-120b` через Groq API (`https://api.groq.com/openai/v1/chat/completions`), `temperature: 0.1`, `response_format: json_schema` со `strict: true`, поэтому ответ всегда соответствует схеме.
- **Резервная модель:** `openai/gpt-oss-20b`. Используется, если основная вернула ошибку или упёрлась в лимит (у Groq лимиты считаются по моделям).
- **Промпт:** опираться только на текст внутри `<lecture>…</lecture>`, не добавлять факты, сохранять термины лекции, для каждого элемента приводить дословную цитату; текст лекции считается данными, а не инструкциями (защита от prompt injection).
- **Пост-обработка:** отбрасываются вопросы с некорректным `correctIndex` или повторяющимися вариантами. Варианты ответа детерминированно перемешиваются, потому что LLM склонны ставить верный ответ первым.

> Почему не `llama3-70b-8192`: на 2026-09-15 Groq больше не предоставляет модели Llama 3 (в `GET /openai/v1/models` их нет), поэтому выбрана `gpt-oss-120b`, которая к тому же поддерживает строгий JSON Schema.

Код: [src/lib/generate.ts](src/lib/generate.ts) — валидация, промпт, схема, вызов API, сверка цитат; [src/App.tsx](src/App.tsx) — интерфейс.

## Как мы проверили точность

Демо-лекция: [demo/lecture_photosynthesis.txt](demo/lecture_photosynthesis.txt) («Фотосинтез», ~3 минуты чтения).

- Прогнали генерацию на демо-лекции и вручную сверили каждый тезис, вопрос и карточку с текстом.
- В первой версии промпта модель добавила в карточку сведения, которых не было в лекции («электроны и протоны»), и писала ATP вместо АТФ. Промпт ужесточили (запрет на подробности «от себя», сохранение терминов лекции, запрет вопросов «что НЕ упоминается»). В повторном прогоне все 20 материалов подтверждены цитатами, лишних фактов не обнаружено.
- Проверили ошибки: пустой текст, короткий текст, набор случайных букв.

## Известные ограничения

- **API-ключ используется в браузере.** Это нормально для локального прототипа, но для публичного деплоя запросы нужно проксировать через сервер, чтобы ключ не был виден пользователям.
- **Бесплатный лимит Groq** (для `gpt-oss-120b` около 8 000 токенов в минуту): несколько генераций подряд могут получить ошибку 429. Приложение переключится на резервную модель или покажет, через сколько секунд повторить.
- **Длина лекции** ограничена 40 000 символов; очень длинные лекции нужно делить на части.
- **Сверка цитат** проверяет, что цитата есть в лекции, но не доказывает, что сам тезис или ответ сформулирован без искажений. Итоговую проверку смысла делает человек.
- Качество зависит от расшифровки: ошибки распознавания речи в исходном тексте попадут в материалы.
- Детектор бессвязного текста эвристический и рассчитан на русский, казахский и английский.
- Нет распознавания аудио/видео и чата по лекции (не входят в обязательный объём ТЗ).
- Материалы не сохраняются между перезагрузками страницы (можно скачать .md).
