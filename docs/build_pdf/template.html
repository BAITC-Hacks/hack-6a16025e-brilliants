1. Что это за проект

Проблема

После лекции студенту приходится самому пересматривать запись или разбирать длинную расшифровку. Чтобы подготовиться к занятию или экзамену, нужно написать конспект, придумать вопросы для самопроверки и сделать карточки для повторения. Это долго, и при ручной работе легко пропустить важную тему или записать её неточно.

Решение

LectureAI — веб-приложение. Студент вставляет текст лекции и нажимает одну кнопку. Примерно через 10–15 секунд он получает четыре вида учебных материалов:

МатериалЧто этоЗачем студенту
КонспектНазвание темы и 2–4 абзаца связного пересказа лекции от начала до концаБыстро понять суть лекции
Тезисы5–8 отдельных главных мыслей. У каждой дословная цитата из лекции, на которую она опираетсяЗапомнить ключевые идеи
Тест5–8 вопросов с 4 вариантами ответа. После ответа видно, верно ли, пояснение и цитата из лекцииПроверить понимание
Карточки6–10 карточек: на лицевой стороне термин или вопрос, на обороте ответ и цитатаПовторить сложные темы

Главная особенность — достоверность

Обычный чат-бот легко «дописывает» факты из своих общих знаний. В учёбе это опасно: студент выучит то, чего лектор не говорил. LectureAI устроен иначе:

  • ИИ получает строгую инструкцию опираться только на текст лекции;
  • к каждому тезису, вопросу и карточке ИИ обязан приложить дословную цитату из лекции;
  • приложение само проверяет, есть ли эта цитата в исходном тексте, и честно показывает результат проверки.

Для кого

Для студента, который готовится к занятию или экзамену. Сценарий из ТЗ: прочитать конспект → пройти тест → вернуться к карточкам по темам, которые вызвали трудности. Интерфейс построен именно вокруг этого пути: из конспекта есть кнопка «Проверить знания», а в конце теста — кнопка «К карточкам».

2. Как пользоваться: путь студента

  1. Ввести API-ключ Groq в поле в правом верхнем углу (один раз, браузер его запомнит).
  2. Вставить текст лекции в большое поле. Для демонстрации есть ссылка «Вставить пример лекции» (лекция про фотосинтез).
  3. Нажать «Сгенерировать материалы» (или Ctrl + Enter). Пока ИИ работает, виден пошаговый индикатор: «Читаем текст лекции → Выделяем главные мысли → Составляем тест и карточки → Сверяем цитаты с лекцией».
  4. Прочитать «Конспект». Внизу показано, сколько материалов подтверждено цитатами, и есть кнопка «Проверить знания».
  5. Посмотреть «Тезисы» — под каждым приведена цитата «Из лекции: …».
  6. Пройти «Тест». Нажать вариант: верный подсветится зелёным, неверный — красным. Появятся пояснение и цитата. Счёт «Верно: X из Y» обновляется, точки внизу показывают прогресс. В конце — итог и кнопки «Пройти снова» / «К карточкам».
  7. Повторить «Карточки» — нажать на карточку, чтобы перевернуть её (3D-анимация), листать кнопками «Назад» / «Вперёд».
  8. При желании — «Сгенерировать заново» или «Скачать .md» (все материалы одним файлом).

3. Как устроено приложение

Архитектура

Приложение — это одностраничный сайт, который целиком работает в браузере. Отдельного сервера у проекта нет: браузер сам отправляет текст лекции в ИИ-сервис Groq и получает ответ.

Браузер пользователя (LectureAI)

  • интерфейс: поле лекции, вкладки, тест, карточки
  • проверка введённого текста
  • формирование запроса к ИИ
  • проверка ответа ИИ и сверка цитат
  • экспорт в Markdown
⇄
HTTPS

Groq API (облако)

  • адрес: api.groq.com/openai/v1/chat/completions
  • основная модель: openai/gpt-oss-120b
  • резервная модель: openai/gpt-oss-20b
  • возвращает JSON строго по заданной схеме

Groq разрешает запросы напрямую из браузера (заголовок CORS access-control-allow-origin: *, проверено). Поэтому для прототипа сервер-посредник не нужен.

4. Как работает ИИ — пошагово

Ниже весь путь от нажатия кнопки до готовых материалов. Шаги 1 и 4–6 выполняет код приложения, шаги 2–3 — языковая модель.

→
3. Модельgpt-oss-120b пишет материалы
→
4. Контрольструктура, индексы, дубли
→
5. Сверкацитаты ищутся в лекции
→
6. Показвкладки интерфейса

Шаг 1. Проверка текста до обращения к ИИ

Функция validateLecture срабатывает сразу при нажатии кнопки. Если текст не подходит, запрос в интернет не отправляется, и пользователь сразу видит понятную ошибку. Проверки:

  • поле пустое → «Нет текста лекции»;
  • меньше 50 символов → «Текст слишком короткий, введите лекцию»;
  • больше 40 000 символов → «Слишком длинный текст»;
  • текст похож на бессмыслицу → «Текст не похож на лекцию». Признаки: букв меньше 55% видимых символов; меньше 8 слов; меньше 70% слов содержат гласные (у набора случайных согласных гласных нет); меньше 8 разных букв (например, «аааааа»); больше 20% «слов» длиннее 25 букв.

Шаг 2. Что отправляется в ИИ

Запрос состоит из двух сообщений. Системное сообщение (промпт) задаёт роль и правила. Сообщение пользователя содержит лекцию, обёрнутую в теги <lecture>…</lecture>: так модель отличает данные от инструкций. Полный текст промпта:

{{PROMPT}}

Параметры запроса

Шаг 3. Строгая JSON-схема ответа

JSON — формат структурированных данных, который программа может надёжно разобрать. Схема описывает, какие поля обязаны быть в ответе и какого они типа. Режим strict не позволяет модели вернуть что-то другое, например обычный текст вместо структуры.

Пример фрагмента реального ответа модели на демо-лекции:

{
  "question": "Какой фермент фиксирует углекислый газ в темновой стадии?",
  "options": ["фотосинтаза", "рубиско", "лактатдегидрогеназа", "цитохром c"],
  "correctIndex": 1,
  "explanation": "Ключевой фермент, связывающий CO₂, называется рубиско.",
  "quote": "Ключевой фермент, который связывает углекислый газ, называется рубиско."
}

Повторы и резервная модель

Приложение делает до трёх попыток: основная модель → ещё раз основная → резервная openai/gpt-oss-20b. Правила:

  • ответ пустой, JSON битый или структура неполная → следующая попытка;
  • лимит запросов (ошибка 429) → сразу резервная модель, потому что у Groq лимиты считаются отдельно для каждой модели;
  • неверный ключ (401/403), слишком длинный запрос (413) или нет сети → повторять бессмысленно, пользователь сразу видит сообщение;
  • общий таймаут на все попытки — 90 секунд.

Шаг 4. Контроль ответа

Даже при строгой схеме код не доверяет ответу вслепую (функция normalize):

  • если is_lecture = false, показывается причина от модели («Текст не похож на лекцию»);
  • у всех строк обрезаются пробелы, пустые элементы удаляются;
  • вопрос теста отбрасывается, если в нём меньше 2 вариантов, correctIndex выходит за пределы списка или варианты повторяются;
  • если после чистки пуст хотя бы один из четырёх блоков, ответ считается неудачным и запрос повторяется;
  • если конспект пришёл одним длинным абзацем, он делится по предложениям примерно на три абзаца для удобства чтения;
  • любая неожиданная ошибка при разборе превращается в сообщение «Ошибка генерации, попробуйте еще раз», а не в падение приложения.

Перемешивание вариантов ответа

Языковые модели часто ставят правильный ответ на первое место. Поэтому варианты перемешиваются, и счётчик correctIndex пересчитывается под новый порядок. Перемешивание детерминированное: порядок вычисляется из текста вопроса, поэтому он не «прыгает» при перерисовке экрана.

Шаг 5. Сверка цитат с лекцией

Это ключевой механизм достоверности. Для каждого тезиса, вопроса и карточки функция isGrounded ищет цитату в исходном тексте:

  1. Лекция и цитата нормализуются: нижний регистр, «ё» → «е», знаки препинания отбрасываются, остаются только слова.
  2. Если цитата целиком встречается в лекции как последовательность слов, она подтверждена.
  3. Иначе цитата делится на триграммы — тройки подряд идущих слов. Если не менее 80% троек есть в лекции, цитата тоже подтверждена. Так допускаются мелкие расхождения, например пропущенное слово.
  4. Цитата короче 3 слов не подтверждается.
Пример. Цитата «Ключевой фермент, который связывает углекислый газ, называется рубиско.» после нормализации превращается в «ключевой фермент который связывает углекислый газ называется рубиско». Эта последовательность слов есть в лекции, значит цитата подтверждена.

Что видит пользователь:

  • подтверждена → под элементом «Из лекции: «…»»;
  • не найдена → честная пометка «Обобщение по лекции — дословный фрагмент не найден»;
  • в конспекте сводка: «N из M материалов подтверждены цитатой из лекции».

Шаг 6. Показ результата

Данные попадают в состояние results, и React отрисовывает четыре вкладки. Счётчики на вкладках показывают количество тезисов, вопросов и карточек. Ответы теста и позиция в карточках сбрасываются при каждой новой генерации. Если пользователь запустил новую генерацию, пока шла старая, результат старой будет проигнорирован.

5. Как система борется с выдуманными фактами

В проекте несколько независимых уровней защиты: если один не сработал, остаются другие.

#МеханизмКак работает
1Правила в промптеТолько сведения из текста; никаких дат, имён, чисел и определений «от себя»; термины — как в лекции; нет вопросов о том, чего в лекции нет
2Низкая temperature (0.1)Модель выбирает самые вероятные формулировки, а не «сочиняет»

Честное ограничение. Сверка доказывает, что цитата есть в лекции, но не доказывает, что сам тезис или ответ пересказан без искажений. Поэтому цитата показывается рядом с формулировкой: студент может сам сравнить их за секунду.

7. Как мы проверяли качество

Демонстрационная лекция

Файл demo/lecture_photosynthesis.txt — лекция «Фотосинтез — как растения превращают свет в энергию», около 2 900 символов, примерно 3 минуты чтения. Темы: определение и уравнение фотосинтеза, хлоропласты (тилакоиды, граны, строма), хлорофилл, световая стадия (фотолиз воды, АТФ, НАДФН), темновая стадия (цикл Кальвина, рубиско), факторы скорости, значение фотосинтеза. Текст содержит только устоявшиеся учебные сведения.

Итерация 1: найденные проблемы

Мы вручную сверили каждый элемент первого прогона с текстом лекции:

  • карточка про фотолиз утверждала, что образуются «электроны и протоны» — в лекции этого нет;
  • модель писала латиницей «ATP», «NADPH», хотя в лекции «АТФ», «НАДФН»;
  • один вопрос был негативным: «Какой фактор НЕ влияет…» с ответом «Гравитация» — лекция о гравитации ничего не говорит.

Исправление

В промпт добавлены три правила: каждое утверждение должно прямо подтверждаться лекцией (без механизмов и частиц «от себя»); термины сохраняются в написании лекции; вопросы о том, чего нет в лекции, запрещены.

Итерация 2: результат

8 тезисов, 5 вопросов, 7 карточек — все 20 элементов подтверждены цитатами. При ручной сверке лишних фактов не найдено. Термины совпадают с лекцией. Время генерации — около 10 секунд.

10. Известные ограничения и планы развития

Ограничения

  • API-ключ используется в браузере. Для локального прототипа это допустимо. Для публичного сайта запросы нужно проксировать через сервер, чтобы ключ не был виден посетителям.
  • Лимиты бесплатного тарифа Groq. Несколько генераций подряд могут упереться в лимит токенов в минуту (ошибка 429). Приложение переключится на резервную модель или скажет, сколько подождать.
  • Длина лекции ограничена 40 000 символов.
  • Сверка цитат проверяет наличие цитаты в тексте, но не точность пересказа.
  • Качество зависит от расшифровки: ошибки распознавания речи в исходном тексте попадут в материалы.
  • Детектор бессмыслицы эвристический и рассчитан на русский, казахский и английский.
  • Нет распознавания аудио/видео и чата по лекции — по ТЗ это необязательные функции.
  • Материалы не сохраняются после перезагрузки страницы (их можно скачать в .md).
  • Если в системе включено «уменьшение движения» (reduced motion), карточки переворачиваются без анимации — это сделано специально для доступности.

Что можно сделать дальше

  1. Серверный прокси для API-ключа и публичный деплой.
  2. Загрузка аудио/видео с расшифровкой через модель распознавания речи.
  3. Чат по лекции, который признаёт, когда в тексте нет ответа (п. 7.1 ТЗ).
  4. Интервальное повторение карточек: показывать чаще те, на которых студент ошибся.
  5. Сохранение истории лекций и материалов.
  6. Второй проход ИИ-«проверяющего», который оценивает точность каждого пересказа относительно цитаты.
